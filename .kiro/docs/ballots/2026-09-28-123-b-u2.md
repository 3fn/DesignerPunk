## 4. Forks — for Peter's ruling, with the author's recommendation

### F-1 — which first-render rates are baselines

**The tension, in the author's own requirements text** (a defect to fix, not a question to answer in conversation):
- Req 11.5.3: U2 *"produces a BASELINE, not a detection"* for the `no-consumer-counterpart` rate.
- Req 11.5.7: the assent rate is, *"like every row in that block: baseline in 123, detector from the second population onward"*.
- Req 11.5.8: *"the first render SHALL NOT be the release at which the ritual-stub rate is read as a baseline"*.
- Task 15 records both rates in a block headed `first render — not a baseline`.

The texts agree that **nothing is a detector inside the first render**. They disagree on whether the first render **baselines** the `no-consumer-counterpart` rate.

- **(a) Per-metric, recommended; this is the draft text.** The first render is a baseline for the `no-consumer-counterpart` rate (11.5.3) and not for the assent rate or the refusal count (11.5.8).
  - *For*: every requirement clause holds for the metric it names. The `no-consumer-counterpart` rate measures the author's disposition choices, not a signer's rote assent, so the rote-assent reason 11.5.8 gives does not reach it.
  - *Residual*: 11.5.7's "baseline in 123" for the assent rate holds **only if Spec 123 renders a second population** (a U3–U5 release that re-judges a delta). Otherwise the assent baseline falls after 123.
- **(b) Whole first render is not a baseline.** Replace the `**Populations**` sentence with:

  ```
  **Populations**: Spec 123's first render (U2b) is recorded in a block headed `first render — not a baseline` for all three metrics; each metric's baseline is the next render population and its detector runs from the population after
  ```

  - *For*: one rule, and Task 15's block heading reads literally.
  - *Against*: it reverses 11.5.3's stated baseline, which would need a requirements erratum.

  rule: "Every package-scope reference (.kiro/steering/, src/, .kiro/agents/, dist/) SHALL match package.json's name scope — no stale-scope references survive a scope change (Spec 101 publish-readiness)"

## 6. Counter-argument (fold-back applied)

**The proposal**: add three rates to the counting block now, and fix L686.

**Counter-argument 1: the block is already long.** Adding metrics whose detectors cannot fire until a later population is ceremony today.
- **Folded in**: the item carries only the three rates Req 11.5 names and no new instrument. The first-render heading exists so the first population cannot be misread as the rote-assent baseline, which is the one misuse the requirements name.
- **Survives**: the item is paid for now and pays off later. If 123 renders no second population, the assent rate's first useful reading happens outside this spec.

**Counter-argument 2: self-attested inputs.** Every counted row is self-attested by the seats being measured. The profile author writes the dispositions; the owners write the signatures.
- **Folded in**: the spot-check fraction is the one independent read, and it is counted.
- **Survives**: a rate over self-attested rows measures **consistency, not truth**. The spot-check has no floor, following the precedent of effort by signal. A 0% spot-check fraction at volume is legal under this text. That is Stacy's call to tighten, and this ballot does not make it for her.

**Counter-argument 3: M2 scope** (option (B) fixes drift 123 did not cause). Surfaced as fork F-2, not absorbed.
