## The defect

`generateHeader` for Kotlin emits a header comment, `package com.designerpunk.tokens`, a blank line, and `object DesignTokens {` — nothing else. No `import` line is emitted anywhere in the file. The body then uses the Compose `Dp` extension `.dp` 65 times and the colormath `Oklch(...)` constructor plus `.toComposeColor()` 99 times, none of which resolve without imports.

## Two separate missing imports — one is already on record, one is not

1. **`androidx.compose.ui.unit.dp`** (Compose UI) — needed for the 65 `.dp` uses. A Compose-UI requirement, independent of the colour library. **Not previously recorded as a defect.**
2. **The OKLCH constructor and `.toComposeColor()`** — the generator names colormath (`AndroidFormatGenerator.ts:742`); INSTALL.md L172 names `github.com/ajalt/colormath` as a dependency the consumer adds. The dependency question (declare it, or emit native colour literals) is `2026-10-03-native-generator-findings-for-spec-129-intake.md` Item 1 / Item 2 and its fix shape; this record does not re-argue it. What this record adds is that even with the dependency present, the file still emits no `import` for it.

(`Typography(...)` is constructed 39 times and is defined nowhere in the file either; Kenya's iOS run reported the same missing `Typography` on Swift — see the 2026-10-03 record, Item 1. Noted, not separately classed here.)
