## Seat-brief template (interim home; moves to `scripts/seat-brief-template.md` with item 2)

A brief for a **signing or confirming act** (signing-act ballot M1) carries these steps in this order. A brief writer copies them; they are not paraphrased.

1. **Read first.** Before anything else, print the whole unit with the print mode, one call per unit, and read its output:
   `npx tsx tools/agent-generator/regrounding/verify-signing-chain.ts --print '<record file>#<anchor>'`
   For a confirmation the target is the operative-set record (`canonical/operative-sets/<file>.yaml#<anchor>`), and the output is the canonical unit. For a signature the target is the dispositions row (`canonical/profiles/consumer/<file>.dispositions.yaml#<anchor>`, `#frontmatter:<path>` for a frontmatter row, `#<member id>` in `_shared.dispositions.yaml`), and the output is the canonical unit and the row's whole consumer rendering. Print on a clean tree: the output's `read at` line names the commit it read and any uncommitted change to a path it read. After any change to the unit, the rendering or the row (a regeneration included), print again before the act. **The brief does not give the target hash or the author's recomputed value.** It names only the unit, the record file and the reason it is stale.
2. **Recompute, then compare.** The print's `canonicalHash` (and, for a signature, `renderedHash`) line is your recomputation: the same computation as the freshness sweep's (fixture PF2). Only then compare it with the freshness sweep's value (`npm run -s check:122:diff-guard`) and the overlay pin. If they differ, stop and report; do not act.
3. **Write the record.** The read line says "the whole unit, from the print-mode output at `<sha>`" (for a signature, "the whole unit and its rendering, from the print-mode output at `<sha>`"), where `<sha>` is the commit on the output's `read at` line. Never a line range.
4. **Commit in the governed form, `governance/signing-seat-brief.md` § "The commit line": each row's signature (or confirmation) and its sheet section in one commit, several rows of one dispositions file in a commit if you like, in its own tool call, with no push in the chain:**
   `git commit -q -F - <<'EOF' && git log -1 --format='%H %s'` (the message as a heredoc, ending at `EOF`)
   (or `git commit -q -m "<subject>" -m "<body>" -m "Agent: <Seat>` + newline + `Co-Authored-By: …" && git log -1 --format='%H %s'`).
   *(Step 4 amended 2026-11-08 by ballot 2026-11-08-signing-act-shape-review item 8 (site 8), at its application PR 1; this supersedes #790's "to be made to agree when it next moves", because signing briefs copy this template verbatim. Superseded text, kept verbatim: "4. **Commit in the proven form, one act per commit, in its own tool call, with no `-q` and no push in the chain:** `git commit -F <message-file> && git log -1 --format='%H %s'` (or `git commit -m "<subject>" -m "<body>" -m "Agent: <Seat>` + newline + `Co-Authored-By: …" && git log -1 --format='%H %s'`).")* The `Agent:` and `Co-Authored-By:` trailers share the message's final paragraph. Never amend, rebase or reset.
5. **Push in a separate call.** Report the line `git log -1` printed.
