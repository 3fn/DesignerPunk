## The defect

1. **The suggested fix points at a directory that doesn't exist.**
   - `recommendedSteeringDir` (`src/cli/sync/SteeringDirCheck.ts` L91–92) swaps the `.kiro/steering` segment for `governance` and keeps any prefix.
   - Pre-123 `init` wrote the **bare** value `./.kiro/steering`. For that value the recommendation becomes `./governance`, and a consumer repo has no such directory.
   - On a terminal, sync asks `Update MCP_STEERING_DIR to 'governance/' in the above config(s)? [Y/n]` (L134). **The default is yes**, and L160 writes the recommended value. Pressing Enter therefore produces a docs MCP that indexes nothing.
   - The code has shipped since v13.0.0 (e83ce803, 119-A).
   - **15.0.0 raises the stakes**: `sync --migrate-legacy` now removes the copied steering docs first. The stale path then holds 9 docs, where before it held the full copied set.
2. **The advice in the "already has an entry" warning names the wrong command.**
   - `src/cli/shared/mcpConfig/kiro.ts` L135 and `src/cli/shared/mcpConfig/cc.ts` L75 both print: `…already has '<key>' entry; left unchanged. If outdated, delete the entry and re-run init, or update manually.`
   - In a born or migrated repo, `init` is the once-ever birth event. The command that rewrites MCP wiring is **`attach --target=<t>`**.

## Fix shape

1. **The recommendation.** When the stale value carries **no package prefix** (the pre-123 bare `./.kiro/steering`, with or without a trailing slash), recommend the **template value** and never `./governance`.
   - Read the template value from `src/cli/templates/mcp-config.json.template` (L9: `"MCP_STEERING_DIR": "./node_modules/@3fn/core/governance"`). Don't hard-code a second copy.
   - The prefixed case (`./node_modules/@3fn/core/.kiro/steering`, which becomes `./node_modules/@3fn/core/governance`) keeps its current swap.
2. **The attach advice.** In a born or migrated repo, the "already has an entry" advice names `attach --target=<t>`, not `init`. This applies at both sites, `kiro.ts` and `cc.ts`.
   - If the string moves into `errorCatalog.ts`, it moves together with a pinning test.
3. **Tests.**
   - The pre-123 bare value `./.kiro/steering` gets the template value as its recommendation, and applying the fix writes that value.
   - The prefixed value keeps its swap.
   - The attach advice string names `attach`.

**What this also fixes.** It corrects the degraded-index state (F4a: migration leaves kiro's docs MCP at 9 docs, because sync classes the legacy entry as "yours" and won't manage it) for any consumer who accepts the corrected prompt. A non-terminal run stays advisory, but it will now advise a value that works.
