## The class of problem
A guard that runs INSIDE an existing required lane (a Jest test selected by a lane's config) has no liveness signal of its own: the lane's selection floor asserts only "≥ 1 resolved test file", so one guard file falling out of `testMatch` goes undetected while the suite stays green. The coverage map cannot show such guards either: its columns are the required CI contexts (`tools/agent-generator/coverage-map.ts` `CHECK_CONTEXTS`), and its surfaces exclude shipped hand-authored content (`governance/` has 0 rows). First instance: Spec 123 Task 23's audience-banner guard (`scripts/audience-banner/__tests__/audience-banner.test.ts`, lane `lane-functional-root` via `npm run test:scripts`); same shape: the completion-claims suites. Consult record: Lina + Stacy, cross-read, 2026-10-13 (U4 session; both converged on this order).

## Step 1 — named-guard selection floor (Thurgood executes; Stacy specifies fixtures + keeps the ARMING read)
The registry `.github/in-lane-guards.json` (`{"version": 1, "guards": [{file, config, context, record}, …]}`, one entry per in-lane guard file: the audience-banner guard; the floor's own test; every `governance/classification-map.md` row whose `checks:` names a test file inside a required lane — enumerated at execution and listed in the PR, so the PR itself leaves no unregistered in-lane guard). A new step inside `lane-functional-root` runs `scripts/ci/check-in-lane-guards.ts`: fails on an empty registry; for each entry confirms the file and config exist and that the file appears in `npx jest --config <config> --listTests`; prints the scoped line `N registered in-lane guards; N selected` — a claim over registered guards only, never every in-lane guard. Cost: one registry + one PR under the grant above. **Residual**: the registry is a hand-kept list; an unregistered guard is invisible to it (smaller and more visible than no registry; the LENS question 6 and claims passes are the backstop). *(Original plan, superseded by the ruling: Stacy as owner via a P1 `lane-timing.yml`-only PR.)*
