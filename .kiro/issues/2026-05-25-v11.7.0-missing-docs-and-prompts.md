# @3fn/core Feedback: v11.7.0 Missing Documentation & Agent Prompt Updates

**Date**: 2026-05-25
**Reporter**: Leonardo (Product Architect)
**Package version**: 11.7.0
**Priority**: Medium — tooling works but agents lack awareness
**Category**: Documentation gap

---

## Issue

v11.7.0 shipped product token tooling (Specs 108 + 109) but did NOT include:

1. **A steering doc for product token authoring** — expected to bring the steering doc count from 87 → 88. No new `.md` file exists in the package's steering directory.
2. **Agent `.json` prompt updates** — Leonardo, Stacy, and implementation agents (Sparky, Kenya, Data) should have updated prompts referencing product token awareness, the `get_product_tokens` MCP tool, and the authoring workflow.

## Impact

- Agents consuming the package don't know product tokens exist unless they're told in-session
- The `get_product_tokens` MCP tool is available but no agent prompt references it
- Product token governance (rationale requirements, promotion signals, color governance) has no steering doc to enforce it
- New products initializing from the package template won't have product token guidance

## Expected Deliverables

### Steering Doc (new)
A `Product-Token-Governance.md` (or similar) covering:
- Authoring workflow (`product/tokens/*.yaml` format)
- Validation CLI (`npx designerpunk validate --product-tokens`)
- Governance rules (rationale on hard values, ref resolution, color governance)
- Litmus test (component token vs product token vs system token)
- Promotion path (promotionCandidate flag → Lessons Synthesis Review → Ada evaluation)
- Naming conventions (camelCase in YAML, `--product-{category}-{name}` in CSS output)

### Agent Prompt Updates

| Agent | What to add |
|-------|-------------|
| Leonardo | Product token authoring as part of screen specification workflow; `get_product_tokens` as a queryable tool |
| Stacy | Product token promotion monitoring during Lessons Synthesis Reviews; `promotionCandidate` flag awareness |
| Sparky | Product token consumption (`dist/product/ProductTokens.web.css`); `--product-*` naming convention |
| Kenya | Product token consumption (`dist/product/ProductTokens.ios.swift`); `Product*` namespace |
| Data | Product token consumption (`dist/product/ProductTokens.android.kt`); `Product*` namespace |

### Package README
Should mention product tokens as a capability alongside system tokens and components.

---

## Interim Workaround

For this project, we'll document the product token workflow in a product-level steering doc ourselves (per Spec 003 Req 5 AC 4). This unblocks our work but doesn't fix the package-level gap for future consumers.
