## What is wrong

Read at `2a3a2e678`. `governance/Component-Development-Guide.md` § "Component Token Files" runs L567 to L673 (the ballot's "about L562–600" was a pre-application estimate; the section is about 107 lines, not 39).

1. **The example file does not exist, and nothing has its shape.** L577–595 shows `ButtonCTA/tokens.ts` exporting `buttonCTATokens`, a plain object of strings (`paddingX: 'space.inset.100'`, `background: 'color.action.primary'`, `borderRadius: 'radius100'`). `src/components/core/Button-CTA/` has no tokens file; it consumes system tokens directly in its three platform files. Of the seven token files under `src/components`, five are `*.tokens.ts` (`Button-Icon/buttonIcon.tokens.ts`, `Avatar-Base/avatar.tokens.ts`, `Input-Radio-Base/radio-sizing.tokens.ts`, `Input-Checkbox-Base/checkbox-sizing.tokens.ts`, `Button-VerticalList-Item/Button-VerticalList-Item.tokens.ts`) and two are `tokens.ts` (`Badge-Label-Base`, `Badge-Count-Notification`). All seven call `defineComponentTokens()` and export the branded result.
2. **It teaches the wrong job for the file.** L571 says the file "defines **which tokens** the component uses, not **how** they're implemented", and L669 repeats it ("The component tokens file only defines which design system tokens the component uses"). A component token file defines **new component tokens**, each referencing a primitive with a stated reason, so the pipeline can emit them. The list of which system tokens a component consumes is the schema's job (`.schema.yaml`; Lina's charter, schema authoring rule). Read against the one rule this ballot installs (a component token exists only when no semantic or primitive token fits, and is created at the Matrix's checkpoint), a file that merely lists semantic tokens is a file that should not exist.
3. **The example's own entries contradict the order.** `borderRadius: 'radius100'` is labelled "references primitive token" with no check that a semantic radius token fits first, and `minWidth: 'space400'` takes a primitive for a size. The example teaches the exact skip the ballot's rule forbids.
4. **The platform-specific half (L598–673) is sound as a statement but hangs from the wrong file.** Its three consumption examples (`ButtonCTA.web.ts` CSS custom properties, Swift constants, Kotlin constants) are the Cross-Platform Token Consumption teaching that already has its own section; here each one is presented as the output of the nonexistent `buttonCTATokens`. The "What If Platform Requirements Don't Fit" subsection (iOS 44 pt touch target, Android ripple, web focus-visible) stands and is true.

## Fix shape

A section rewrite, owner Lina, by a ballot measure proposal (it is a governance doc): the section (a) takes its example from a real file (`Button-Icon/buttonIcon.tokens.ts`, already quoted at L203), (b) says a token file defines component tokens only where the Matrix's step 3 gate was passed, (c) points consumption to the schema and to Cross-Platform Token Consumption instead of teaching it from a made-up map, and (d) keeps the "Don't Fit" subsection. Two adjacent edits ride with it: the reading-list line at L54 ("**Component Token Files** (platform-agnostic token references)") changes with the section, and the two ownership-tree lines `Component Token Files (tokens.ts)` at `governance/rosetta-system-principles.md` L515 and `governance/stemma-system-principles.md` L820 use the bare `tokens.ts` name that only two of seven files carry; those are Ada's (Rosetta) and Lina's respectively, to be read in the same PR, not decided here.

**Surviving counter-argument**: the section is small beside the guide's other debts, and the real pattern is one query away, so a rewrite may rank below component work Peter wants first. That is why this is `release:next:phase-1` and not `manual`: P2 obligations lapse visibly under rule 11, and the alternative (a P3 `manual`) would let a wrong teaching sit at two walks unremarked. Peter's call, at the first lapse, between spec, drop and fix-now.

**Unchecked here**: the typography and radius token names in the example (`typography.buttonMd`, `radius100`) were not looked up; `color.action.primary` and `color.text.default` exist (`src/tokens/semantic/ColorTokens.ts` L328, L399). The fixing PR checks every name it keeps.
