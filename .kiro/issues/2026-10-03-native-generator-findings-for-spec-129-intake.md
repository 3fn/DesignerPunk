## Item 1 (Kenya): `DesignTokens.ios.swift` and `ComponentTokens.ios.swift` do not typecheck together, even setting the theme question aside

**Evidence: VERIFIED by Kenya's `swiftc -typecheck` run on this tree's `dist/`, not a packed tarball.**
- The two files together: `cannot find 'SizingTokens'` (42), `'SpacingTokens'` (14), `'BorderWidthTokens'` (2). This is the 2026-08-13 issue, re-measured by a compiler for the first time.
- `DesignTokens.ios.swift` alone: `cannot find 'Color'` (198), `'oklch'` (18), and also `'Typography'`, `'Animation'` and others.

**Ada's reading.**
- The file imports `UIKit` only (`dist/DesignTokens.ios.swift:8`). It uses SwiftUI's `Color` and a `Color.oklch(...)` initializer (99 occurrences) that no shipped file defines and the package does not declare as a dependency.
- `src/providers/iOSFormatGenerator.ts` names ChromaKit for it (Kenya cites `:310`, `:592`; Ada did not re-read those two lines).
- The theme-surface absence is a separate cause, tracked in the issues above.

**Unverified.**
- Whether ChromaKit provides `Color.oklch(L, C, H)`. Kenya: "names", not "provides".
- A probable redeclaration of `AvatarTokens` (`Avatar.ios.swift:35` vs `ComponentTokens.ios.swift:14`). Kenya read it but did not compile it.

## Item 2 (Data, extended by Ada): WCAG override lines are emitted in CSS `oklch(…)` syntax on both native platforms

**Evidence: VERIFIED by reading.**
- `TokenFileGenerator.ts:960-971`: `toIOS` and `toAndroid` convert only `rgba(...)` strings. Anything else is returned unchanged (`if (!m) return rgba;`, `:962` and `:969`).
- WCAG values are OKLCH strings, so they pass through verbatim:
  - Android, `:1002-1015`: `dist/DesignTokens.android.kt:683` → `val color_feedback_info_text_wcag = oklch(0.4 0.183 310)`.
  - iOS, `:989-1000`: `dist/DesignTokens.ios.swift:685` → `public static let colorFeedbackInfoText_wcag: UIColor = oklch(0.4 0.183 310)`.
- Space-separated arguments are not valid Kotlin or Swift call syntax.
- Data reported the Android half. Ada found the iOS twin while checking it. Kenya's count of 18 `cannot find 'oklch'` errors is consistent with it.

**Unverified**: whether the iOS `_wcag_` lines account for all 18 of Kenya's `oklch` errors.

## Item 3 (Kenya and Data): product tokens that reference theme-varying tokens emit code against a theme type or CompositionLocal nothing defines. One related gap emits a name that does not exist.

**3a: VERIFIED by reading.**
- `src/build/product/emitters/SwiftEmitter.ts:11,49-56` emits `public extension <Name>Theme { var product…: Color { self.<prop> } }`.
- `src/build/product/emitters/KotlinEmitter.ts:11,33,49-52` emits `Local<Abbr>Theme.current.<prop>`, with `import com.designerpunk.tokens.Local<Abbr>Theme`.
- Neither type is emitted by `generate`: the theme-type generator `generateThemeOverrideBlocks`, `TokenFileGenerator.ts:1028`, has no non-test caller. The 2026-06-28 issue covers that root cause; this is its product-token consequence.

**3b: VERIFIED by reading; Data reasoned it; Ada traced it.** The token index and the native generators use two different theme-varying sets, by design:
- **The index** gets the base-scoped set (light vs dark only; `generateTokenFiles.ts:200-208`, returned at `:331-336`).
- **The native generators** exclude the registry-wide set (dark ∪ wcag ∪ dark-wcag keys; `:182-191`, passed at `:233`, applied at `TokenFileGenerator.ts:843-846`).

So a token overridden only by WCAG is marked `themeVarying: false` in the index, with a static native path, but it is **absent** from native output. `color.action.primary` is the example:
- `token-index/semantics.yaml:246-254`: `themeVarying: false`, `ios: colorActionPrimary`, `android: color_action_primary`;
- `dist/DesignTokens.ios.swift` has 0 occurrences of `colorActionPrimary`.

Consequences:
- A product token whose `ref:` is such a token emits `DesignTokens.colorActionPrimary` / `DesignTokens.color_action_primary` (`SwiftEmitter.ts:63-67`; Kotlin `formatKotlinValue`), a name that does not exist.
- The application MCP's `get_token_details` reports the same nonexistent native name to agents.

**Unverified**: not run with a product-token fixture. The committed `token-index/` may be stale (`2026-09-26-committed-token-index-stale.md`), but the two-set logic above is in the source either way.
