## 1. Question
Does a semantic or discriminative matcher find discovery targets the lexical matcher misses — on query surfaces the frozen 119-A oracle does not exercise — and if so, is the gain attributable to semantics in general (a local open model suffices) or to a specific vendor model? Invariant across every outcome: **no probability enters the live `matchConfidence`, and no model dependency enters the live path.**

## 2. Premises (all VERIFIED 2026-10-07 unless marked)
- Docs harness `scripts/discovery-dry-run.ts` → `mcp-server/src/discovery-dry-run/discovery-dry-run.ts`; pure `scoreConcept`; `PASS_RANK_BOUND = 2`; PASS = rank ≤ 2 AND tier ∈ {strong, partial}; hidden default: a missing tier scores as 'partial' (wrapper needed for untiered arms).
- Oracle `scripts/__fixtures__/discovery-oracle.ts`: 83 concepts, frozen, never edited/extended (119-B R3 AC3). Dry-run 2026-10-07: 83/0/0, rank-1-strong **77/83** (78 on 2026-08-02 — one more concept at rank 2). **The oracle is the lexical matcher's training set** (floor 62/18/3 → aliases seeded from its own WEAK/MISS list → tie-breaker): it cannot compare arms; it is the regression check and prompt-calibration data only. It has NO negatives, so it cannot set an abstention floor.
- Docs matcher indexes title, headings, description, purpose, aliases (high); relevantTasks (medium); path (low); stop-word filter; body not indexed; `STRONG_COVERAGE_THRESHOLD = 0.5`.
- Components matcher: highSignal = name, family, purpose, contract concept keys + categories; lowSignal = whenToUse, contexts, alternatives[].reason, description; whenNotToUse excluded; `aliases` never populated and low-signal by rubric (intentional — Lina); no stopwords, no plural folding; rank = coverage then alphabetical, tier-blind. Live confident-wrong results and copy-pasted sibling metadata: see Lina's defect record. No components oracle or dry-run exists; ~8 calibration queries in `tool-boundary.contract.test.ts`.
- No ML / embedding / LLM dependency in any package.json; MCP servers run offline from compiled output.
- Unmeasured surfaces: Sparky, Kenya, Data, Stacy (119-B case study § 1); Leonardo has 2 oracle entries on docs and none on components, where he is the primary consumer.
- **Zero real screens exist** (`find_screens` → `[]`). Every query any author writes is imagined usage. Leonardo's actual selection path: layout template → experience pattern → `find_components({context})` exact match → `get_prop_guidance` → `get_component_full` → `validate_assembly`. Keyword discovery is a MINOR path for him (one-off elements; existence checks such as "is there a switch?") — and there a `strong` on a wrong component is the harm that matters: he would spec around it and never report the gap.
- Repo is PUBLIC (`gh repo view`): text sent to a vendor arm is public text.
- Jev, from official docs: `POST https://api.typesafe.ai/v1/systemone`, Bearer key; request `{ state, model, questions }`; state = string | JSON | array of text; questions evaluated in parallel and in isolation; primitives `noul` (yes/no → `noul` ∈ [0,1]), `choice` (criteria map, ≤ 255 options, "reliable to ~240"; → `choice`, `probabilities`, `confidence` = (p_max − 1/n)/(1 − 1/n), a shape statistic, **no calibration claim**), `score` (≤ 10 levels). Model ids `jev-1.13.0` (pinnable), `jev-latest`. $0.042 per million input tokens, output free. Python SDK `typesafe-sdk`; `RateLimitError` exists. Cookbooks: re-ranking = one Noul per (query, candidate) pair; classification = one Choice over 75 groups with confidence routing (65 % forced → 90 % in the ≥ 0.9 bucket). UNVERIFIED: whether the console key is self-serve or gated; state size limit; rate-limit numbers; determinism.

## 3. The staged design (converged across the three passes)

**Stage 0 — Lina's live defect fixes (issue-driven, NOT the study).** Stopword filter, plural folding, tier- and name-aware tie-breaker (Thurgood consulted), and — per fork F1b — de-duplication of the copy-pasted sibling metadata. Contamination rule: driven only by on-record defects; Q3 and the sealed seat queries are invisible to the fixer until the fixes merge.

**Stage 1 — docs side on the shipped matcher (~1.25 Thurgood sessions).** Calibration-only set first (Thurgood; ~8 docs near-miss negatives + the ~8 tool-boundary components queries; frozen; never scored; prompt iterations ≤ 5, logged). Then blind queries: Leonardo (lead, ~15–20), Sparky, Kenya, Data, Stacy (~10 each), written without seeing the index; Leonardo's "would a product architect ask this" filter runs BEFORE the freeze. Thurgood writes single-answer keys. Components-shaped queries are SEALED (committed by hash, hidden from Lina until Stage 0 merges) as raw input to Q3. Run the lexical arm only. Closes 119-B's named coverage gap on its own.

**Volume gate.** Bucket every miss: tokenizer/rank defect | alias- or metadata-fixable | structural. Gate counts only the last two. ≤ 3 → hand-fix (docs: aliases; components: purpose/whenToUse phrasing), findings doc, stop.

**Components round (after Stage 0 merges; ~2 Lina sessions).** Q3 ≈ 50: 34 positives (≥ half phrased without the target's own name words), ~6 multi-answer with acceptable-answer sets, ~10 negatives. Jurisdiction: Leonardo rules whether a query underdetermines the sibling choice; Lina rules whether a sibling satisfies the stated need; challenges recorded as fixture comments pre-freeze. Frozen after Stage 0 merges; run against the pre-fix SHA (before) and post-fix (after). Primary = rank 1 within the acceptable set; docs primary stays rank ≤ 2; both report both plus tie-group size. Promotion of Q3 to a standing components oracle: fork F3.

**Stage 2 — semantic arms (only if the gate trips; the vendor arm gated on access).**
- **B — local semantic**: pinned open embedding model (id + hash), offline; chunking = doc text + each heading, best match (one blob of 2,833 headings is a strawman); components: one text per component from the parity fields.
- **C — Jev**, two methods, both run; agreement between them is itself a finding:
  - *C-point* (re-ranking recipe): one request per (query, candidate) pair over EVERY candidate — no shortlist, so independent of A and B. `state = { query, candidate: { id, <parity fields> } }`; one `noul` "Does this candidate answer the query?" with pre-registered true/false criteria; rank by `noul`. ≈ 8k calls per run.
  - *C-list* (75-group recipe): one `choice` per query; criteria = candidate id → description built from PARITY FIELDS ONLY (`what` = purpose + description; `examples` = whenToUse + contexts) + `none_of_the_above`. Scoring: positives — `none` excluded from the ranking, `none` as top pick = MISS; negatives — correct iff top pick is `none` or top probability < floor. "parity + `not_for` (whenNotToUse)" runs as an EXTENSION reported separately.
  - *C-rubric (CANDIDATE — not pre-registered; needs Lina's and Thurgood's read; see fork F9)*: instead of one verdict per candidate, a fixed rubric of typed yes/no questions per (query, candidate) — purpose addresses the query? / query names a deciding detail the candidate lacks? / candidate internal-only? / does ANY candidate exist? — each a probability; the tier DERIVED from them by pre-registered thresholds; the per-question answers are the reported evidence (inspected on split cases only, never keyed). This tests a judgment layer, not a matcher, and is the arm that actually answers Peter's hybrid question ("model for confidence, agent for context"). If adopted it should DISPLACE C-list rather than join it. Source: `.kiro/docs/discovery-signal-architecture-notes.md` § 4.
  - Prompts pre-registered; calibrated only on the oracle and the calibration-only set. Floors pre-registered at 0.5 and reported as uncalibrated. ×3 runs; response `model` field recorded; variance reported. Adapter SOURCE committed under the grant paths (Python venv in scratchpad; nothing added to any package.json; nothing in either MCP server; key in `.env`, never committed). Parity text exported from the ASSEMBLED ComponentMetadata (post-Stage-0 indexer; component-meta SHA pinned).
- Inputs = exactly the fields the lexical matcher indexes; whenNotToUse excluded; props/tokens/READMEs only in extension E1 (body text, ceiling measurement). Alias split docs-only.
- Rank-only R@1 / R@2 for ALL arms incl. A; A's tiered PASS on its own line. A and B once with hashes; C ×3. Negatives: confident-wrong iff any `strong` (A) / any candidate above floor (B, C) in the top 2 — fork F6 asks for top 3. Q2 and Q3 reported separately.
- Cost: three runs of both C methods < $3 API spend.

**Decision rules (pre-registered).** O1: ≤ 3 structural AND ≤ 8 fixable misses → findings doc + issue closes; **no write to the `certainty-calibration` register row** (it governs agent behaviour, not matcher quality; `governance/**` moves only by ballot). O2: ≥ 9 one-fix misses AND ≥ 70 % of all → charter an offline alias/metadata-proposal tool (any model; human confirms before anything lands). O3: ≥ 4 owner-confirmed structural misses → ballot (likely collapses into O2: a live semantic tie-breaker ships a model and loses hand-reconstructability — Spec 121's objection to scores is reconstructability, not calibration; a well-calibrated C does not answer it). Vendor claim only if C beats B by ≥ 4 split cases in every one of 3 runs — and is a finding about `jev-1.13.0` on one date. Answer-key errors counted and excluded, never edited after.

## 5. Surviving objections (no revision absorbed these)
- Nothing in production prompted this; a vendor launch did. The live defects (Lina's record) are the real finding and need no study.
- **Imagined usage**: zero screens, zero query logs; more authors cannot create a log. (Leonardo; Thurgood; Lina's "author bias".)
- **Wrong scale**: at 34 components the hard choice is between siblings, not finding the family; the result will not carry to product scale. (Lina; Leonardo.)
- **On components, the real counterfactual is an agent reading the ~1.7k-token catalog** (`get_component_catalog`), which agents already do for free; a listwise C win measures catalog-reading vs keyword search, not Jev vs anything. (Lina; Leonardo; Thurgood's conditional.)
- ~75–125 authored positives detect gross gaps only; a null result proves little.
- Thurgood's conflict of interest → orchestrator checks the split table.
