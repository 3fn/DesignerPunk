# Inbound from Spec 119 (Steering Progressive Disclosure Redesign) — for Spec 122

**Date**: 2026-06-27
**Status**: 119 is pre-formalization (design-outline only) and split into **119-A (foundation, before 122) → 122 → 123 → 119-B (routing + measurement, after)**. This note registers what 119's pre-formalization reconciliation hands to 122. None of it unblocks 122's own gate (still Spec 118's direction decision — see `inbound-from-118.md`); it's captured so it isn't lost across the split.

---

## 1. Candidate deliverable — a *generated* human-facing documentation TOC (NEW; decide during 122 formalization)

119 dropped its proposed **agent-facing** Documentation Directory (a hand-curated, `manual`-inclusion cross-domain catalog). `find_docs` (Spec 121, shipped) subsumes the agent use case — concept-indexed, self-maintaining, portable — so a hand-curated directory is pure drift surface for agents.

What that decision left open is a **human** need 119 deliberately pushed out of its own scope: a curated, domain-grouped "lay of the land" a *person* (Peter, a new contributor) reads to orient to the governance corpus. `find_docs` is a query tool, not that narrative overview.

**Why this lands on 122, not 119:** the only acceptable form of this artifact is **generated from the doc index, not hand-curated** — the same drift objection that killed the agent-facing Directory applies to a human one. "Emit an artifact from a canonical source" is structurally 122's pattern (it's the token-pipeline model 122 is built on), not 119's (relocate + serve). So *if* we build it, it belongs to 122's generator surface as another generated output.

- **Not urgent / not on any critical path.** `find_docs({ list: true })` already yields a paginated catalog that covers ~80% of the acute "what exists" need today.
- **If adopted:** generate a domain-grouped TOC of the `governance/` corpus (post-119-A relocation) from the same index data `find_docs` uses; commit it; guard it with 122's regenerate-and-diff guard so it can't drift. Owner: Civitas (governance), generated by the pipeline.
- **Decision point:** 122 formalization. Default recommendation is **defer unless a concrete human-orientation pain shows up** — don't pre-build it.

## 2. Routing-table content is 122's canonical-source job (already 119's design bet — restating the concrete rows)

119 Decision 1/4 put activation logic in per-agent prompts and explicitly rejected hand-editing 8 prompt files; 119-B expresses agent routing as **canonical-source content 122 generates**. Two concrete rows surfaced during 119's pre-formalization that should live in 122's canonical source, not as hand-edits:

- **`find_docs` discovery row.** Audited 2026-06-27: only Thurgood's prompt routes to `find_docs` (`.kiro/agents/thurgood-prompt.md:308`); the other 7 agents have no concept-discovery route. The fix is a `find_docs({ concept })` / `find_docs({ list: true })` row in the canonical source, propagated to all agents at generation time. (The tool is live + self-describing in every agent's tool list, so this is a reliability/activation gain, not a blocker.)
- **Module-Resolution Contract row (from Spec 118).** Ada (primary) / Thurgood / Lina get a routing row to the contract (`get_section` on `Rosetta-System-Architecture.md` § Module-Resolution Contract). See 119's `inbound-from-118.md` Hand-off 1 — it's explicitly a generated row once 122 lands.

These are not new 122 scope — they're instances of "agent prompts become generated outputs." Capturing the concrete rows so they survive the 119-A → 122 → 119-B sequence.

## 3. Addressing change in 119-A that 122's generated prompts must honor

119-A folds in a **uniform per-doc `id` addressing** change at the Docs MCP (resolve `get_section` by a frontmatter `id` carried on all docs, not physical path) so relocation `.kiro/steering/` → `governance/` doesn't break the 60 hardcoded path references across the 8 prompts. **Identifier form RESOLVED (2026-06-27): uniform `id` on all 89 docs** (kebab-slug by convention), not basename/slug-derived — see 119 design-outline § "R2 Review Resolutions" R1. **Implication for 122:** generated agent prompts must reference docs by their **`id`**, not a physical `governance/...` path — so any future relocation/rename stays transparent and the generator output is location-independent. The address grammar is forward-shaped for section IDs too: `docid#sectionid` (119 Resolution R4 / roadmap Gap 7) — emit doc-level `id` now; section-level `#sectionid` slots in later without regenerating differently.
