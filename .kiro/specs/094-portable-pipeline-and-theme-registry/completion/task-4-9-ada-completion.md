## What Was Done

Modified the token generation pipeline to exclude theme-varying color tokens from the static iOS and Android output. These tokens now live exclusively in the theme types (protocol/data class) generated by Tasks 2.3/2.4. This prevents dual-pattern consumption where components could reference either the old static property or the new theme-aware property.

### Generator Changes

**`TokenFileGenerator.ts`**:
- Added `excludeTokenNames` parameter to `generateSemanticSection`
- Added `themeVaryingTokens` field to `GenerationOptions`
- `generatePlatformTokens` passes `themeVaryingTokens` for iOS and Android, but NOT for web (CSS custom properties must remain in `:root` for the base theme)

**`generateTokenFiles.ts`**:
- Computes `themeVaryingTokens` from ThemeRegistry overrides + base light/dark differences
- Passes the set through to `generateAll`

### Tokens Removed from Static Output

iOS (10 tokens removed):
- `colorFeedbackInfoText`, `colorFeedbackInfoBackground`, `colorFeedbackInfoBorder`
- `colorActionPrimary`, `colorActionNavigation`
- `colorContrastOnAction`, `colorStructureCanvas`
- `colorStructureBorderSubtle`, `colorBackgroundPrimarySubtle`
- `colorIconNavigationInactive`

Android (15 lines removed — same tokens, some with `_light`/`_dark` variants):
- Same semantic tokens as iOS, with Android-specific formatting

### What's Unchanged

- **Web CSS**: All tokens remain in `:root` — CSS custom properties are the base theme and must be present for inheritance
- **WCAG override blocks**: Still present on all platforms (these are theme-specific overrides, not static properties)
- **Non-color tokens**: Spacing, sizing, typography, radius, etc. — unchanged across all platforms

### Snapshots Updated

iOS and Android snapshots updated to reflect the new output. CSS, DTCG, Figma, and ComponentToken snapshots unchanged.
