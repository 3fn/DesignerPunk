# Product

## Register

brand

## Users

Design system architects, design engineers, and AI-forward product teams who need systematic infrastructure for human-AI collaboration. They arrive from GitHub, conference talks, or word of mouth, already frustrated that existing design systems weren't built for machine consumption. They're looking for a working example of what AI-first design infrastructure looks like, not a tutorial about why it matters.

## Product Purpose

DesignerPunk is an ecosystem that enables humans and AI agents to collaborate on building software products through shared precision. It provides mathematical token foundations (Rosetta), behavioral component contracts (Stemma), and governance infrastructure (Civitas) that AI agents can query, validate against, and build with. Success is measured by whether an AI agent can use the system correctly on first encounter without prior training.

## Brand Personality

Electric, systematic, punk. DesignerPunk speaks with the confidence of mathematical precision and the irreverence of someone who believes the tools to create shouldn't be gatekept. The tone is **direct** (no hedging), **precise** (token names, not vague descriptions), and **principled** (every decision has a traceable rationale). Not corporate. Not academic. Infrastructure with attitude.

Three-word personality: **electric, precise, punk**.

## Anti-references

- **Generic SaaS marketing**: hero-metric layouts, identical-card feature grids, "boost your productivity" copy, purple-to-blue gradients
- **Design system documentation clichés**: sterile white pages with component thumbnails in a grid, "getting started" tutorials that assume ignorance
- **AI-tool aesthetic**: dark mode with neon accents, glassmorphism, glowing particles, cyan-on-black terminal cosplay
- **Corporate design systems**: safe, neutral, inoffensive palettes designed by committee. Beige. Gray. "Professional."
- **Hedging language**: "might", "could", "consider". DesignerPunk is opinionated. It picks a direction and commits.

## Design Principles

1. **The system IS the demo.** Every surface built with DesignerPunk should demonstrate the system's capabilities through execution, not explanation.
2. **Mathematical, not arbitrary.** Every value derives from a formula. Every relationship is traceable. Nothing is "because it looks right."
3. **Precision enables collaboration.** Ambiguity is the enemy of partnership. "space150" is unambiguous; "medium padding" is not.
4. **Punk is a stance, not an aesthetic.** The tools to create should not be gatekept. The system levels the competitive field.
5. **Evolve, not just ship.** The system is designed to grow. Every decision is documented. Every spec is preserved. Institutional knowledge compounds.

## Accessibility & Inclusion

Baseline: WCAG 2.1 AA on all surfaces. Key commitments:
- Dual theme support: Original (maximum aesthetic impact) + WCAG 2.2 (accessible while maintaining character)
- Day/night modes for both themes
- Color contrast verified mathematically through token relationships, not eyeballing
- All interactive elements keyboard-navigable with visible focus states
- `prefers-reduced-motion` respected (iOS uses spring animations; web/Android use expo-out curves)
- Semantic HTML first, ARIA as supplement
- Touch targets meet platform minimums (44pt iOS, 48dp Android, 44px web)
