## Surviving counter-argument to this block

**The C8(c) probe (row 5.2) is a same-harness observation placed inside a cross-harness run.** It opens Claude Code in a CC-born clone, which is the easy branch Req 15A.4 warns about, and it writes `.claude/settings.local.json` and probably `mcp-server/logs/` into the clone before the Kiro joiner starts. The Kiro join does not read `.claude/`, and the record will name both files. A stricter design would clone twice: one clone for the probe, one for the join. That costs one more `git clone` and nothing else, and I would take it if the orchestrator prefers.

**Ruled 2026-10-15 (orchestrator)**: clone twice. The C8(c) Claude Code probe runs on its own fresh clone of `born-cc`, kept separate from the Kiro join clone, and is labelled as a same-harness observation inside the `join-cc-to-kiro` record. This counter-argument is therefore absorbed.
