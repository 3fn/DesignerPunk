## Notes bearing on the rows (not criteria)

- **N1 — Req 13's warning has no catalog text.** Design § Error Handling reads `consumer degradation | (unchanged; warning, exit 0)`, and Req 13.5 requires a test that asserts the warning TEXT. 16.1 authors the string in `errorCatalog.ts`, and the test asserts it string-equal. Adding a design-catalog row for it is an erratum for the orchestrator to route. It is not an instrument gap: the instrument (10.1/10.2) is built here.
- **N2 — Row 10's new comment text is unspecified.** Design C1 says only "its example comment updated". 16.3 authors it with Ada consulted. This is content, not an instrument.
- **N3 — The adapter registry file is outside the grant.** Task 16's Primary Artifacts list `adapters/{cc,kiro}.ts`, not `adapters/index.ts`, where `AdapterContext` lives. 16.1 plans its adapter edits inside `cc.ts` and `kiro.ts` with no `AdapterContext` field. If a field turns out to be needed, the PRIMARY stops and reports; nothing is routed around.
- **N4 — `generate.ts` is outside the grant (Peter's ruling 5).** The prepack derive calls its exported functions without editing it. The consumer bundle must not carry `generate.ts`, because its CLI `require.main` block, its live-registry path and its lazy requires would ride into `dist/generator/consumer-entry.js`. 16.1 therefore loads `generate.ts` only on the steward side, and records how.
- **N5 — `require.main` in a bundle.** Measured at this block's writing, esbuild 0.27.2 with `--format=cjs` binds an ESM-syntax module's `require.main === module` to the BUNDLE's `module`, so every bundled module's CLI block runs when the bundle is executed directly. A scratch bundle printed its inlined module's main-block marker. `build:generator` must neutralize this (row 1.5), and the paths test's spawn spy (row 1.11) is the runtime check.
