### THE L3-B2 ADJUDICATION — option (ii), by derivation

**`init` detects a repo that already has a design system and REFUSES by default, printing the joining path.** Written at 15A.3.

**Why this is a derivation and not a new ruling.** Leonardo measured the defect: the Spec-102 guard skips files that exist and **copies every file that does not**. So a founder who deleted a palette family from his own token tier — *his right, because the language is his* — gets **ours re-added by a teammate's accidental re-run**, announced as *"N new files"*. **That is ours flowing into theirs after birth, which the identity statement says stops "by definition."** Option (i) would describe that; option (ii) prevents it. Model B says `init` runs **once per design system, ever**, and this project's standing posture is that a rule which matters is enforced mechanically rather than taught. **A birth that can be silently repeated is not a birth.**

**Competing principle, searched for and not found**: the Spec-102 guard exists so re-running is *safe*, and refusing is the stronger form of safe; P5's scaffolder boundary is untouched; a founder's early mistake is covered by the flag. **So I decided it**, and the requirement says so, so Peter can overturn it cheaply if he reads it as a CLI-behavior decision (Leonardo's own framing).

**The flag, named: `init --re-scaffold`** — and **under it `init` reports every file it would re-add before adding it**, so resurrection is never silent even when chosen. The name may change at design; the semantics may not. **Birth detection**: config **or** copied token tier present = born; **one without the other refuses with a named explanation** rather than guessing, which addresses half of Leonardo's surviving counter. The other half — one more flag to learn for a rare legitimate re-scaffold — is **recorded as the accepted cost of a loud refusal over a quiet resurrection.**

### THE 11.4 CONTAINMENT PIN — drafted for Stacy to pin
