## 1. What changed

- **`harness/android/`** is one Gradle build (`593c7d4ef`, `5fd5edaca`):
  - `settings.gradle.kts`, `build.gradle.kts`, `gradle/libs.versions.toml` (the pinned versions) and `gradle.properties` (plain console, no parallel execution, no configuration cache), with `tokens/`, `probe/` and `dp/` build files. Each module is a `com.android.library` with the Compose compiler plugin.
  - `:tokens` compiles the generated Kotlin only. `:dp` compiles every non-test packaged `.kt` and the generated Kotlin, with Icon-Base's `res/` as its resources and the AGP namespace `com.designerpunk.components.core` (the package `IconBase.android.kt` refers to `R` in). `:probe` is 4.2's.
  - The modules name no source file. They read explicit file lists from `HARNESS_LANE_DIR` (`tokens.sources`, `dp.pkg.sources`, `dp.gen.sources`, `dp.res`) and stop at configuration when a listed file is missing, because a source directory that does not exist is skipped silently.
- **`harness/android/lane.ts`** computes, per tier, the explicit source files (sorted, package files first) and the floor at run time. It reads the generated Kotlin's folder from the manifest's `platformOutputs.android` (which `consumer.ts` read from the consumer's config), never a hard-coded path. It leaves out the package's root token files, checks that no two files of the `:dp` set share a base name, prints the invocation and the `:dp` file order, runs `./gradlew --continue :tokens:compileDebugKotlin :probe:compileDebugKotlin :dp:compileDebugKotlin` once, and writes one run file per context.
  - The floors: `gen` is the `.kt` count `generate` reported in the manifest; `pkg` is the same exclusion rule applied to the packed tarball's file list. The compiled counts in the run files are the counts Gradle printed (`harness-sources:`).
- **The wrapper** (`5fd5edaca`): `gradlew`, `gradlew.bat` and `gradle/wrapper/gradle-wrapper.jar`, generated by Gradle 9.8.2 from its checksum-verified zip. `gradle-wrapper.properties` names Gradle 9.8.2 in `distributionUrl` and sets `distributionSha256Sum` (`21bd5da2…89607`, Gradle's published value). The jar's sha256 `3b8a2577…68e98` equals the one Gradle publishes for 9.8.2.
- **`harness/android/README.md`**, `.gitignore`.

## 3. Application-time adaptations

1. **The tarball also ships `dist/DesignTokens.android.kt`.** The criterion and Req 2.4 name `dist/ComponentTokens.*`. The first real run stopped in the duplicate-name guard on `DesignTokens.android.kt`, so the lane leaves out both root token files. Tasks amendment 3 wrote this into Task 4's criterion; the entry is in `task-4-instruments.md`.
2. **The invocation is configured in `gradle.properties`, not on the command line.** The harness README says the run uses `--console=plain` and `--no-parallel`; putting both in `gradle.properties` keeps the printed invocation exactly `./gradlew --continue :tokens:compileDebugKotlin :probe:compileDebugKotlin :dp:compileDebugKotlin`. The lane prints it with the `HARNESS_LANE_DIR` it set, in a subshell form.
3. **`HARNESS_LANE_DIR` is an environment variable**, not a `-P` property, for the same reason.
4. **The counts are Gradle's.** Each compile task prints, in its `doFirst`, how many explicit files it was given, and the run file's `compiled` takes those numbers. A compile task that never starts prints nothing, and its count reads 0.
5. **`gradle-wrapper.properties` is the committed file, not the generated one.** The two differ only by two `retries` lines and key order.
6. **`:dp`'s namespace** is not stated in the design; § 2 now says it.
7. **The `setSource`, `res.srcDir`, `androidComponents.pluginVersion` and configuration-name lines that rested on training data** all ran in that first real run.
