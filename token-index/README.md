# token-index/

Machine-readable token index consumed by MCP servers at runtime.

## Files

| File | Contents |
|------|----------|
| `primitives.yaml` | All primitive tokens — family, value, formula, platform names |
| `semantics.yaml` | All semantic tokens — category, primitive references, theme-varying flag, platform names, consumers |
| `components.yaml` | All component tokens — component, primitive references, platform names |

## Platform names

Each entry's `platforms` block gives, for `web`, `ios` and `android`, what that platform's generated output defines for the token:

- **one name** (a string): `--space-inset-200`, `spaceInset200`, `space_inset_200`;
- **several names** (a list), for a composite the generator writes as several definitions: on web a typography token is one custom property per property (`--typography-body-md-font-size`, `-line-height`, …), a shadow is its composite `--shadow-container` and one property per part, and a semantic motion token is `--motion-float-label-duration` and `-easing`; on iOS and Android a semantic motion token is the members of its type (`MotionFloatLabel.duration`, `MotionFloatLabel.easing`);
- **`null`**, when that platform's output carries no name for the token, with the reason in the entry's `platformNotes` (e.g. `elevation.*` is Android-only: "Use z-index + shadow tokens instead").

iOS and Android names are members of `DesignTokens` (nested ones as `Type.member`, e.g. `Duration.duration150`). A `theme.` name (`theme.colorActionPrimary`) is a token the native generators leave out of `DesignTokens` for the theme types; those types are not emitted yet (Spec 129). The `theme.` prefix follows the set the native generators use, which includes the WCAG overrides; the `themeVarying` flag is narrower, base light/dark only (Spec 117), so the two can differ.

`src/generators/__tests__/tokenIndexPlatformNames.test.ts` checks every name against freshly generated output.

## Generated By

`src/generators/generateTokenIndex.ts`, invoked during:
- `npx designerpunk generate` (pipeline CLI)
- `npm run generate:platform-tokens` (`scripts/generate-platform-tokens.ts`, in this repo)

Regenerated automatically whenever the pipeline runs. Do not hand-edit.

## Consumed By

- **Application MCP** (`application-mcp-server/src/indexer/TokenIndexer.ts`) — indexes tokens for `search_tokens`, `get_token_details`, `get_token_family`, `get_token_consumers`
- **Product MCP** (`product-mcp-server/src/indexer/TokenRefResolver.ts`) — resolves product token `ref` values against the index

## Commit Policy

**Yes — commit these files.** MCP servers read them at runtime without running the pipeline. Keeping them committed ensures MCP queries return current data in any environment (CI, fresh clones, agent sessions).

## Freshness

If token source files change, re-run `npx designerpunk generate` to update the index. The Product MCP warns when a token reference can't be resolved — this usually means the index is stale.
