# Task 3 Summary: The iOS lanes

**Date**: 2026-11-07
**Purpose**: Concise summary of parent Task 3 (Spec 129, Unit 1)
**Organization**: spec-summary
**Scope**: 129-consumer-generation-completeness

## What Was Done

`harness/ios/lane.ts` runs the two iOS harness contexts on a `macos-26` runner. `harness-ios-tokens` compiles the generated iOS token files as one module under Swift 6 and then compiles a generated probe against that module. `harness-ios-components` compiles every non-test packaged `.swift` file together with the generated files under Swift 5, and compiles the generated files alone for the comparator's cross-tier rule. Every flag and the Xcode 26.6 toolchain come from `harness/pins.yaml` § `ios`, and the lane fails a context that runs under a different toolchain. Each stage runs a self-test first, to show the compiler really emits object code and the probe really reads from outside the module.

The probe is generated by `scripts/harness/probe-swift.ts` from the consumer's token index, its registered themes and its product tokens. It reads every iOS name the index gives, every theme colour through every theme instance, every product token, the theme provider and its family, and the environment key. Each group has its own count line, and a group whose count is short fails the context. The probe takes every naming rule from the shared module `scripts/harness/native-rules.ts` and keeps no copy.

## Why It Matters

Every native "compiles" in Spec 129 is accepted by these lanes. A token that the generator forgot, or emitted without `public`, shows up as a compile error from outside the module instead of being found by a person reading text. A dispatched run on the unit branch ran both contexts to a PASS against their committed lists, which means the failures match the lists, not that the code compiles.

## Key Changes

- `harness/ios/lane.ts` (stages T, P, C and T5, file order and floor, the toolchain read, the self-tests, the per-run instance check) with `selftest/` fixtures and a README for the workflow.
- `scripts/harness/probe-swift.ts` and `probe-swift.test.ts` (86 tests, including both contexts end to end against a fake `swiftc`).
- `harness/pins.yaml` § `ios`: Xcode 26.6 (17F113), SDK 26.5 (23F81a), Swift 6.3.3, deployment target 17.0; the last four values were measured by the first `macos-26` run.
- The lane writes its gating results into the run file's `checks`, and the comparator fails the context for any that is not ok.
