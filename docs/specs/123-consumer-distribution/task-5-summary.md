## What Was Done

`npx designerpunk sync` was re-scoped to Model B. **Our content never flows into the consumer's.**
- `sync` no longer manages or writes her token tier (`src/tokens`), `src/types`, or the pre-123 component copies.
- It manages only what the manifest recorded as ours:
  - in U1, the still-copied agents, steering and governance docs (file grain);
  - DesignerPunk's MCP keys in `.kiro/settings/mcp.json`, `.mcp.json` and `.claude/settings.json` (key grain, compared by parsed value).
- **Nothing applies before the report prints.** Off a terminal, nothing is written without `--apply`; on a terminal, one confirmation. A conflict applies only with `--overwrite <path>`, and a deleted file only with `--restore <path>`.

The manifest moved to `designerpunk.manifest.json` at the repo root.
- It has a stable key order and one entry per line (merge-friendly), and records `posture` and `origin`.
- A pre-123 `.kiro/sync-manifest.json` is converted and relocated.
- Entries under paths `sync` no longer manages are pruned, with one report line per group. The `src/types` line warns that her token tier still needs those files.

Pre-123 consumers get a **component-copy migration**.
- Each copy is judged against what each version actually shipped. The content is fetched the way she installed (her own npm setup, cache first), using the copy transform loaded from each version's own tarball.
- Unmodified copies can be removed, forks relocated to `src/components/<Name>/`, and her own components moved alongside. This happens only with `--migrate-components`.
- Undecidable copies read "cannot tell", with a three-cause message and an actionable remedy.
- Two old-template repairs are offered only after the migration fetch, each behind its own flag: the `.npmrc` GitHub Packages pin (`--repair-npmrc`) and `tsconfig.test.json`'s raw-src re-pins (`--repair-tsconfig`).

## Why It Matters

Under Model B, tokens are the consumer's language and components are our updating surface. A `sync` that kept refreshing her token tier would have silently undone her birth event. One that only compared whole files would have treated every consumer edit to a shared JSON config as a conflict, or overwritten it. The manifest-as-membership rule means a key or file is managed only because we recorded emitting it, never because it matches our prefix. Migrations judged against shipped content, rather than a first-sync baseline, stop a pre-sync edit from being mistaken for pristine and deleted.
